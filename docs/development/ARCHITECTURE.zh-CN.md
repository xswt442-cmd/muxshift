# 工程架构

[English](ARCHITECTURE.en.md)

当前仓库是工程骨架，已实现的部分只有 Go Core 的会话配置模型。尚未实现媒体接入、解码、缓存、按时间对齐的同步、混音或播放。

## 模块及边界

| 目录 | 当前状态 | 职责边界 |
| --- | --- | --- |
| `core/` | 会话配置模型 | 共享的媒体会话配置与控制契约所在位置 |
| `desktop/` | 文档占位 | MyGo 桌面适配，不承载共享业务逻辑 |
| `web/` | 文档占位 | 浏览器界面及浏览器媒体能力适配 |
| `extension/` | 文档占位 | 经用户授权的浏览器会话内集成 |
| `testplace/` | 本地忽略目录 | 实验、临时记录、Agent 工作文件 |

客户端与 Core 的预期依赖方向为 `desktop → core ← web`；浏览器扩展通过显式协议衔接，不直接耦合桌面 UI。这里描述的是模块所有权约束，不代表这些调用已经实现。

## Core 会话模型

`core.Session` 只保存配置，不保存播放状态。一个会话持有它读取的媒体源、源中发现的音视频与字幕轨、把多条轨绑到同一参考轨的同步组、决定显示什么与听见什么的场景，以及把场景交给某个能力的输出。每条轨最多属于一个同步组。每次操作要么完整生效，要么不改动会话；被拒绝的操作不记录事件；删除媒体源会同时删除它的轨以及对这些轨的全部引用。

## Core 事件时间轴

`core.Timeline` 用 `targetMediaTime = sharedEventTime + mappedOffset` 把同一个共同事件时间映射到各条轨的媒体时间。偏移为正表示该轨的媒体时钟走在前，按直播跟随需要把它延后同样的时长；偏移为负表示该轨还没到达当前事件的内容。设置偏移是替换而不是叠加，因此同一校准结果应用两次不会累积。没有偏移的轨按 `not_aligned` 报告，不会被放到猜测的时间上。

`core.Playhead` 是共同事件时钟：从零开始且处于暂停，只有播放时才前进；跳转保留当前暂停或播放状态。暂停、恢复与跳转一起移动这个时钟和每一条轨的目标时间，从不改动已存的偏移。这两个类型都不解码媒体、不操作播放器、不访问网络。

## 边界原则

- 支持独立媒体源和多个同步组；不把「双路」作为 Core 的固定数量限制。
- 媒体源、音轨、同步关系、输出布局是不同概念。`core` 已固定它们的形状与事件时间轴；媒体处理尚未实现。
- 浏览器会话访问和跨端媒体能力存在差异；不能默认 Web 可以读取 Edge Cookie 或任意第三方媒体流。
- Go Core 与 MyGo 的 UI 生命周期分离。媒体引擎、音频推理及传输协议尚未确定，不将候选技术写成已集成依赖。
- `testplace/` 不进入版本控制；正式文档仅维护稳定且可验证的仓库事实。

目前可执行的基础验证是仓库根目录的 `go test ./...`，它运行 `core` 的会话测试。
